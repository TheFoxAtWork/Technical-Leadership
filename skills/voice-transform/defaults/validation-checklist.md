# Voice Transformation Validation Checklist

**Purpose**: Pre-delivery checks to ensure transformed content is clear, direct, and professional.

Use this checklist before finalizing any transformation. Not every item will apply to every context, but most should.

---

## I. Structure Checks

### Paragraph Length
- [ ] Paragraphs are 3-5 sentences max (rarely longer)
- [ ] Line breaks create visual breathing room
- [ ] No wall-of-text blocks

### List Usage
- [ ] Numbered lists for sequential steps or when order matters
- [ ] Bullet lists for parallel concepts or options
- [ ] Lists are used appropriately (not defaulting to bullets for everything)

### Scaffolding
- [ ] Complex ideas have clear frameworks (if/then/else, numbered steps)
- [ ] Headers create logical progression readers can follow
- [ ] Structure is explicit, not assumed

### Examples & Grounding
- [ ] Abstract concepts have concrete examples
- [ ] Technical decisions show real-world application
- [ ] Readers can map concept to their own context

---

## II. Tone Checks

### Direct Address
- [ ] "You" is used for positive framing
- [ ] "It/that/this" used for challenges or critique
- [ ] "We" used for partnership (shared work/decisions)
- [ ] No blaming language ("You failed" → "This approach missed...")

### Difficulty Acknowledgment
- [ ] Challenges are named, not glossed over
- [ ] Hard things are called hard ("This is difficult", "This takes time")
- [ ] No false simplification ("Just do X" when X is complex)

### Permission Structures
- [ ] Reader given permission to be imperfect
- [ ] Struggle is normalized
- [ ] Progress is defined realistically

### Contractions
- [ ] Natural contractions used ("you're", "it's", "doesn't", "isn't")
- [ ] Not avoiding them for false formality
- [ ] Reads like speech, not stilted writing

---

## III. Vocabulary Checks

### Active Voice
- [ ] Active voice dominates
- [ ] Passive voice only when actor is unknown/irrelevant
- [ ] No passive constructions hiding responsibility
- [ ] Clear who did what

### Specific Verbs
- [ ] Specific action verbs over generic
- [ ] Verbs show concrete action
- [ ] No vague "addressed", "engaged", "leveraged" (unless leverage = mechanical advantage)

### Technical Terms
- [ ] Technical terms used precisely, not as jargon filler
- [ ] Terms are necessary for precision
- [ ] When used, terms are explained or contextually clear

### Corporate Jargon (Avoid)
- [ ] No "synergize", "circle back", "touch base"
- [ ] No "bandwidth" (use "time" or "capacity")
- [ ] No "leverage" unless mechanical advantage
- [ ] Plain language preferred when it works

### Numbers & Specifics
- [ ] Concrete numbers used (3 teams, 6 months, 90 days)
- [ ] Time estimates specific, not vague
- [ ] Quantities named when relevant

---

## IV. Explanation Checks

### Concrete Over Abstract
- [ ] Abstract concepts grounded in relatable scenarios
- [ ] Examples show the concept working
- [ ] Readers can see themselves in the example

### Technical Metaphors
- [ ] Complex ideas use metaphors readers know
- [ ] Metaphors clarify, not obscure
- [ ] Metaphors match audience level (technical vs everyday)

### Meta-Commentary
- [ ] Guides reader through thinking process when needed
- [ ] Signposts transitions ("Here's why", "Let me explain")
- [ ] Not overused (only when genuinely helpful)

### Reader Check-ins
- [ ] Anticipates reader reactions
- [ ] Addresses potential objections
- [ ] Validates confusion before redirecting

### If/Then/Else Structure
- [ ] Complex decisions have if/then/else framing
- [ ] "If" = assumptions/context
- [ ] "Then" = logic/process
- [ ] "Else" = exceptions/caveats

---

## V. Content Authenticity Tests

### The Read-Aloud Test
- [ ] Content sounds natural when read aloud
- [ ] Would work as spoken delivery
- [ ] Pacing feels right (not too fast, not too slow)

### The Authenticity Test
- [ ] Sounds like natural professional communication
- [ ] Not an AI approximation or generic corporate speak
- [ ] Personality is earned through substance, not decoration

### The Audience Test (Context-Specific)

**For Leadership/Formal Contexts (Highest Formality)**:
- [ ] Professional tone maintained
- [ ] Still uses contractions (but fewer)
- [ ] Concrete examples present
- [ ] No emoji
- [ ] Directness + action-orientation preserved

**For Strategic Docs (Medium Formality)**:
- [ ] Balanced professional + personality
- [ ] Technical metaphors encouraged
- [ ] Measured conversational tone
- [ ] Rare emoji if genuinely additive

**For Team/Internal Communication (Conversational)**:
- [ ] Most relaxed voice
- [ ] Meta-commentary welcome
- [ ] Permission structures used
- [ ] Occasional humor when it serves the point

### The Substance Test
- [ ] Personality comes from content (examples, directness), not decoration (emoji, exclamation marks)
- [ ] Not performative or forced
- [ ] Authenticity feels earned

---

## VI. Hedging & Confidence Checks

### No Excessive Hedging
- [ ] No "I think perhaps maybe"
- [ ] No "might possibly be"
- [ ] No "to a certain extent", "somewhat"

### Confident When Appropriate
- [ ] Clear recommendations stated directly
- [ ] "Will" or "does" when outcome is known
- [ ] "This works" not "This might work"

### Genuinely Uncertain When Appropriate
- [ ] Real uncertainty acknowledged directly
- [ ] "I don't know if X, but here's why Y anyway"
- [ ] Doesn't fake confidence or hedge excessively

---

## VII. Formality Calibration (Context-Dependent)

### High Formality Context (Leadership, Formal Reviews, External Communication)
- [ ] Professional tone maintained
- [ ] Direct and action-oriented
- [ ] Contractions still used (but fewer)
- [ ] Concrete examples and data
- [ ] No emoji
- [ ] Technical precision required
- [ ] Avoids overly casual language

### Medium Formality Context (Strategic Docs, Cross-Organizational Updates)
- [ ] Balanced professional + personality
- [ ] Full use of technical metaphors
- [ ] Measured conversational tone
- [ ] Rare emoji if genuinely additive
- [ ] Shows reasoning openly
- [ ] Technical precision + accessibility

### Low Formality Context (Team Updates, Internal Communication, Mentoring)
- [ ] Most conversational voice
- [ ] Meta-commentary encouraged
- [ ] Permission structures used freely
- [ ] Occasional humor when it serves the point
- [ ] Direct access language
- [ ] Still professional (not sloppy)

---

## VIII. Integration Checks (For Automatic Transformations)

### Context Detection
- [ ] Formality level matches detected context
- [ ] If context detection seems wrong, flag for review
- [ ] File path or content markers drove correct formality choice

### Technical Accuracy Preserved
- [ ] All factual claims intact
- [ ] Numbers unchanged
- [ ] Technical terminology correct
- [ ] No meaning drift in transformation

### Annotations Present (If Configured)
- [ ] Major changes documented
- [ ] Reasoning for transformations explained
- [ ] Changes can be validated

---

## IX. Red Flags (Fail Fast)

If ANY of these are present, transformation needs revision:

### ❌ Performative Personality
- Multiple exclamation marks!!!
- Forced enthusiasm
- Emoji storms 🎉🚀✨
- Trying too hard to be relatable

### ❌ Corporate Speak
- "Synergize", "circle back", "touch base"
- "Bandwidth" (use "time")
- "Leverage" without mechanical advantage
- Generic management jargon

### ❌ Vague Language
- "Some challenges"
- "Various approaches"
- "Potential benefits"
- "Certain considerations"

### ❌ Passive Voice Dominance
- "Was done", "were addressed"
- "Has been implemented"
- "Could be considered"
- Hiding agency

### ❌ Missing Scaffold
- Conclusions without reasoning
- Advice without process
- "Just do X" without explaining how
- No examples grounding concepts

---

## X. Pre-Delivery Final Checks

### Quick Scan
- [ ] Read first paragraph: Does it hook and provide context?
- [ ] Read last paragraph: Does it close with action or reflection?
- [ ] Scan headers: Do they create clear progression?
- [ ] Scan lists: Are they scannable and actionable?

### The Professional Test
- [ ] Would this land well with its intended audience?
- [ ] Does it balance professionalism with clarity?
- [ ] Does it demonstrate clear thinking?
- [ ] Is it appropriately formal for the context?

### The Action Test
- [ ] Is it clear what reader should do next?
- [ ] Are action items explicit (who, what, when)?
- [ ] Can reader act on this independently?

### The Learning Test
- [ ] Does this teach "how to think", not just "what to do"?
- [ ] Can reader apply this framework elsewhere?
- [ ] Have you shown the scaffold, not just the conclusion?

---

## Usage Notes

**Not every check applies to every context:**
- Short comment ≠ strategic framework doc
- Team update ≠ formal leadership summary
- Adjust expectations based on content type and audience

**Fail fast on red flags:**
- If you see performative personality, corporate speak, or missing scaffold, stop and revise
- These are non-negotiable quality issues

**When in doubt:**
- Read it aloud
- Ask "Does this sound like natural professional communication?"
- Check against before/after examples
- Default to medium formality (professional + personality)

---

## Checklist for Different Content Types

### Status Update
Focus on: Structure, Specificity, Active Voice, Audience (medium formality)

### Formal Report
Focus on: Formality, Concreteness, Numbers, Audience (higher formality)

### Technical Comment
Focus on: Directness, Technical Precision, Actionability, Brevity

### Team Communication
Focus on: Accessibility, Meta-Commentary, Permission Structures, Conversational Tone

### Strategic Document
Focus on: If/Then/Else, Technical Metaphors, Scaffold Visibility, Examples

### Meeting Summary
Focus on: Action Items, Decision Clarity, Concerns Addressed, Timeline
